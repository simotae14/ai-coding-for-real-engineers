# Instructor Analytics Dashboard

## Problem Statement

Instructors on Cadence have no way to see how their courses are actually performing. There's a per-course student roster (progress, quiz scores) buried inside an individual course's editor, but nothing that shows an instructor, at a glance, how their courses are selling, how many students actually finish them, or where in a course students give up. Instructors have to guess whether a course is doing well or where it's losing people.

## Solution

A new "Analytics" section, linked from the instructor sidebar (below "My Courses"), with two views:

1. A **portfolio page** (`/instructor/analytics`) giving a cross-course overview: a combined revenue trend with a date-range selector, and a sortable table of all published courses with their key sales and reputation numbers.
2. A **per-course drill-down page** (`/instructor/:courseId/analytics`), linked from each row in the portfolio table, showing that course's own revenue trend, its completion rate, and a lesson-by-lesson drop-off funnel so the instructor can see exactly where students stop progressing.

## User Stories

1. As an instructor, I want a dedicated "Analytics" item in my sidebar below "My Courses", so that I can find performance data without digging through individual course editors.
2. As an instructor, I want to land on a portfolio page that summarizes all my published courses, so that I can quickly judge overall performance without opening each course.
3. As an instructor, I want to see a combined revenue trend across all my courses, so that I can track how my overall business is doing over time.
4. As an instructor, I want to pick a time range (7 days, 30 days, 1 year, or all time) for the revenue trend, so that I can zoom in or out depending on what I'm investigating.
5. As an instructor, I want the dashboard to default to a 30-day view, so that I see a recent, relevant snapshot without having to configure anything.
6. As an instructor, I want my selected time range preserved in the URL, so that I can share, bookmark, or reload the page without losing my selection.
7. As an instructor, I want the revenue trend shown as a plain time series without period-over-period deltas or comparisons, so that the chart stays simple and I'm not misled by noisy comparisons.
8. As an instructor, I want a table listing each of my published courses, so that I can compare them side by side.
9. As an instructor, I want to see each course's title in the table, so that I know which row is which.
10. As an instructor, I want to see each course's listed price in the table, so that I have pricing context next to its performance.
11. As an instructor, I want to see revenue generated by each course during the selected period, so that I know which courses are earning the most right now.
12. As an instructor, I want to see units sold (enrollments) by each course during the selected period, so that I can see sales volume, not just revenue.
13. As an instructor, I want "units sold" to count actual enrollments rather than checkout transactions, so that a single team purchase covering multiple seats is reflected accurately rather than undercounted as "one sale."
14. As an instructor, I want to see the number of subscriptions (enrollments) per course during the selected period, so that I can track new-student growth over time.
15. As an instructor, I want to see each course's average rating, so that I can gauge student satisfaction at a glance.
16. As an instructor, I want to see each course's total number of reviews, so that I can judge how much feedback the rating is based on.
17. As an instructor, I want ratings and review counts to reflect all-time data regardless of the selected date range, so that reputation metrics aren't artificially reset when I change the time filter.
18. As an instructor, I want the table sorted by revenue (descending) by default, so that my best and worst performing courses are immediately visible.
19. As an instructor, I want to sort the table by other columns, so that I can investigate different aspects of performance (e.g. highest rated, most enrollments).
20. As an instructor, I want only published courses shown in the table, so that drafts and archived courses don't clutter my sales overview.
21. As an instructor with no published courses, I want to see a clear message ("No revenue data. Publish a course to see the analytics.") instead of empty charts, so that I understand why the dashboard is blank.
22. As an instructor, I want to click a course row to drill into that course's dedicated analytics page, so that I can investigate a specific course in depth.
23. As an instructor, I want to see a course's own revenue trend on its drill-down page, using the same range selector and URL-persisted state as the portfolio page, so that the experience is consistent.
24. As an instructor, I want to see a course's completion rate on its drill-down page, so that I know what fraction of enrolled students actually finish it.
25. As an instructor, I want completion rate computed from actual lesson-progress data rather than relying on a course-level "completed" flag, so that the number reflects real student progress even though that flag isn't populated anywhere in the app today.
26. As an instructor, I want to see a lesson-by-lesson drop-off funnel for a course, so that I can pinpoint exactly which lesson is losing students.
27. As an instructor, I want the funnel ordered the same way students see the course (module order, then lesson order within each module), so that the funnel matches the actual learning path.
28. As an instructor, I want each funnel step to reflect the percentage of enrolled students who completed that lesson, so that I can compare drop-off severity across courses of different sizes.
29. As an instructor, I want each funnel step to also show the absolute number of students who completed that lesson, so that I have concrete counts alongside the percentage.
30. As an instructor viewing a published course with no enrollments yet, I want to see a "No enrollments yet" message instead of broken/empty charts, so that I understand the course simply hasn't had activity yet rather than assuming something is broken.

## Implementation Decisions

- **Routing**: Two new routes following the existing `instructor.*` file-route convention — `instructor.analytics.tsx` (portfolio) and `instructor.$courseId.analytics.tsx` (drill-down). Both routes authorize using the same instructor-owns-course pattern already used by `instructor.$courseId.students.tsx`.
- **Navigation**: A new sidebar entry, "Analytics," added directly below "My Courses" in the instructor navigation, linking to `/instructor/analytics`.
- **Date range state**: Range selector (`7d`, `30d`, `1y`, `all`) is read/written via URL search params (e.g. `?range=30d`), following the existing loader pattern (`new URL(request.url)` + `searchParams.get`) and `useSearchParams` usage already established in `app/routes/courses.tsx`. Default value when the param is absent is `30d`. No period-over-period comparison or delta indicators are shown anywhere.
- **Charting library**: Recharts is added as a new dependency. Used for the revenue time-series (line/area chart) and the lesson drop-off funnel (bar chart).
- **Revenue metric**: Sum of `purchases.pricePaid` for a course (or across all courses, portfolio-level) within the selected date range, bucketed by day for the time series.
- **Units sold / subscriptions metric**: Count of `enrollments` rows created within the selected date range — not count of `purchases` rows. This distinction matters because a single team purchase (via `teams`/`teamMembers`) creates multiple enrollment records from one checkout; the metric must reflect seats/enrollments, not transactions.
- **Price column**: Course's current listed price (`courses.price`), not the realized average price paid (which can vary due to coupon discounts or PPP pricing). Static and always populated, even when there were zero sales in the selected period.
- **Rating / review columns**: All-time aggregates from `courseRatings` (average rating, count of ratings), not scoped to the selected date range.
- **Course filter**: Only courses with `status = 'published'` appear in the portfolio table. Draft and archived courses are excluded entirely.
- **Default sort**: Portfolio table defaults to sorting by revenue (selected period) descending; other columns are also sortable.
- **Completion rate**: Computed live using the existing `calculateProgress` logic (already used in `instructor.$courseId.students.tsx` and elsewhere), based on `lessonProgress` rows — i.e., percentage of enrolled students whose lesson-progress rows show 100% completion. This intentionally does **not** use `enrollments.completedAt`, which exists in the schema but is never set by any current code path (`markEnrollmentComplete` is defined but unused). Fixing that dead field is out of scope for this feature.
- **Completion rate placement**: Shown only on the per-course drill-down page, not in the portfolio table.
- **Drop-off funnel**: For a given course, lessons are flattened into a single sequence ordered by module position, then lesson position within each module (matching the student-facing course structure). Each funnel step represents one lesson; the step's value is the percentage of enrolled students with a `lessonProgress` row of `status = 'completed'` for that lesson (in-progress-but-not-completed does not count as "reached" for this metric). Each bar displays both the percentage and the absolute completed count.
- **Empty states**:
  - Portfolio page, instructor has zero published courses: show message "No revenue data. Publish a course to see the analytics." instead of chart/table.
  - Drill-down page, course has zero enrollments: show message "No enrollments yet." instead of chart/funnel.

## Out of Scope

- Conversion/funnel-from-pageviews metrics (e.g. visitor-to-buyer conversion rate) — no page-view or visitor tracking exists in the codebase, and adding one is a separate, larger effort.
- Refund/cancellation tracking and its effect on revenue — no refund or cancellation table exists in the schema; purchases are treated as permanent.
- Quiz pass rates as a dashboard metric (data exists via `quizAttempts.passed` but is not part of this feature).
- Video engagement metrics (e.g. average watch percentage per lesson from `videoWatchEvents`) as a complement to the drop-off funnel.
- Coupon redemption statistics (redemption counts, discount totals) as a revenue-adjacent metric.
- Fixing/wiring up `enrollments.completedAt` and `markEnrollmentComplete` — completion rate is derived live instead; the dead field itself is left alone.
- Period-over-period comparisons or delta/trend indicators (e.g. "+12% vs previous period") anywhere in the dashboard.
- Showing draft or archived courses in the portfolio table.
- Any admin-facing (cross-instructor) view of this data — this feature is scoped to a single instructor viewing their own courses.

## Further Notes

- This feature builds entirely on the existing schema (`users`, `courses`, `modules`, `lessons`, `enrollments`, `lessonProgress`, `purchases`, `courseRatings`, `teams`/`teamMembers`); no new tables or migrations are required.
- There is currently no charting library and no analytics/dashboard module in the codebase — Recharts and the query/service layer for this feature are being introduced from scratch.
- The four out-of-scope metric ideas (quiz pass rates, video engagement, coupon redemptions, refunds) were deliberately deferred rather than rejected, and are reasonable candidates for a future iteration of this dashboard.
